# Развёртывание

Parent: [[Index]]

## Назначение

FluffBoard уезжает на сервер одним Docker-образом: собранный клиент лежит в `wwwroot` рядом с backend, поэтому у страницы и у `/api` один origin и cookie-сессии не нужен ни CORS, ни отдельный веб-сервер для статики. Образ собирает GitHub Actions на self-hosted раннере и пушит в приватный реестр `docker.barkfluff.com:5000`. Схема повторяет соседний проект BarkFluff, чтобы раннер, реестр и nginx на сервере обслуживали оба проекта одинаково.

## Файлы

| Файл | Содержимое |
|---|---|
| `Dockerfile.slim` | Сборка клиента в Docker и итоговый образ поверх `aspnet:10.0-alpine`. |
| `.dockerignore` | Что не уходит в контекст сборки. `publish/` входит намеренно. |
| `.github/workflows/build-fluffboard.yml` | `dotnet publish` на раннере → login в реестр → версия → build & push. |
| `.github/actions/docker-version/action.yml` | Спрашивает у реестра последний semver-тег образа и инкрементирует patch. |
| `docker/fluffboard/docker-compose.yml` | Подъём доски на сервере; nginx — под профилем `nginx`. |
| `docker/fluffboard/sample.env` | Шаблон окружения: порт, токен GitHub, репозиторий, пользователи. |
| `docker/nginx/fluffboard.conf` | Site-конфигурация nginx: 80 → 443, TLS, проксирование на контейнер. |

## Сборка

| Шаг | Что делает |
|---|---|
| Проверка SDK | `dotnet --list-sdks` должен содержать `10.*`, иначе сборка останавливается с ошибкой. |
| `dotnet publish` | Публикует `backend/backend.csproj` в `./publish` на раннере, `UseAppHost=false`. |
| Login | Заходит в `docker.barkfluff.com:5000` секретами `REGISTRY_USERNAME` и `REGISTRY_PASSWORD`. |
| Compute version | Читает `/v2/fluffboard/tags/list`, берёт наибольший semver и прибавляет 1 к patch; пустой реестр даёт `1.0.0`. |
| Build & push | Собирает `Dockerfile.slim` с контекстом репозитория и пушит два тега: версию и `latest`. |

Триггеры: push в `main`, затронувший `backend/`, `frontend/`, `Dockerfile.slim`, `.dockerignore` или сам workflow, плюс ручной `workflow_dispatch`.

## Развёртывание на сервере

1. Скопировать на сервер каталог `docker/` (нужны `docker/fluffboard/` и `docker/nginx/`).
2. `cp sample.env .env` в `docker/fluffboard/` и заполнить: порт, `GitHub__Token`, репозиторий, пользователи.
3. `docker login docker.barkfluff.com:5000`.
4. `docker compose up -d` — или `docker compose --profile nginx up -d`, если на сервере нет своего nginx.
5. Обновление: `docker compose pull && docker compose up -d`.

Свой nginx на хосте использует ту же `docker/nginx/fluffboard.conf`, в ней меняется только upstream — на `127.0.0.1:<FLUFFBOARD_PORT>`. Сертификаты для контейнерного nginx кладутся в `docker/fluffboard/certs/`.

## Важные детали

Клиент собирается **внутри** Docker (`node:22-alpine`), а `dotnet publish` выполняет раннер. Так на раннере не нужен Node, и это та же схема, что у `BarkFluff.Web`, где в Docker остаётся только Node-часть. Слой `npm ci` переиспользуется, пока `package-lock.json` не менялся.

Итоговый образ на `alpine`, а не на `noble-chiseled`, как большинство сервисов BarkFluff: каталог `data` нужно создать и передать пользователю приложения, а в chiseled нет shell для `mkdir`. Тот же выбор и по той же причине сделан в `BarkFluff.AdminPanel`, где SQLite лежит в `/app/db`.

SQLite живёт в томе `fluffboard_data`, путь задаётся `Board__DatabasePath=/app/data/fluffboard.db` — см. [[backend/Конфигурация]]. Без тома пользователи доски пересоздавались бы при каждом обновлении образа. Пустой том Docker наследует владельца каталога из образа, поэтому `chown` в `Dockerfile.slim` достаточно и `user: root` не нужен.

Внутри контейнера backend всегда слушает 8080 — это порт по умолчанию образов `aspnet`. Наружу публикуется `FLUFFBOARD_PORT`, поэтому 5279 из [[backend/API]] остаётся только development-портом.

`client_max_body_size 6m` в конфигурации nginx обязателен: вложение описания ограничено 5 МБ на стороне backend, а дефолтный `1m` у nginx обрезал бы картинку раньше и загрузка падала бы с 413.

Секреты репозитория: `REGISTRY_USERNAME` и `REGISTRY_PASSWORD`. Телеграм-подтверждения сборки и уведомлений, как в BarkFluff, здесь нет — у FluffBoard одна ветка `main`, и подтверждать каждый push вручную было бы лишним шагом. По той же причине у образа нет суффикса `-dev`.

Версия SDK проверяется как `10.*`, а не фиксированным патчем: BarkFluff ждёт ровно `10.0.110`, и обновление SDK на раннере ломает такую проверку.

Чего в развёртывании пока нет: `HEALTHCHECK` (маршрута `/health` у backend нет), `ForwardedHeaders` и флага `Secure` у cookie-сессии — за TLS отвечает nginx, а backend видит запрос как HTTP, поэтому cookie уходит без `Secure`.
