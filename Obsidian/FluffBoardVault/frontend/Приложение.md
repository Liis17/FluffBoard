# Приложение

Parent: [[Index]]

## Назначение

React-клиент FluffBoard показывает защищённую доску задач одной репозитории GitHub. Пользователь входит по локальным учётным данным, затем создаёт, редактирует и переносит задачи; каждая запись сразу отправляется в GitHub. Экран собран по макету редизайна из `docs/handoff_fluffboard_board/`.

## Файлы

- `frontend/src/App.jsx` — состояние экрана, загрузка данных, синхронизация вида с URL и композиция блоков.
- `frontend/src/api.js` — запрос с cookie-сессией и разбор ошибок API.
- `frontend/src/board.js` — чистая логика доски, см. [[frontend/Доска]].
- `frontend/src/markdown.js` — чистая логика разметки описания, см. [[frontend/Разметка]].
- `frontend/src/components/icons.jsx` — иконки в сетке 24×24: цвет наследуют от текста, размер — от размера шрифта.
- `frontend/src/index.css` — дизайн-токены как CSS-переменные и базовые стили.
- `frontend/src/App.css` — стили всех блоков экрана.
- `frontend/index.html` — подключение шрифтов Manrope и JetBrains Mono с Google Fonts.
- `frontend/vite.config.js` — React-плагин и proxy `/api` на backend development server.

## Ключевые функции `App.jsx`

| Функция | Описание |
|---|---|
| `readView` / `writeView` | Держат режим, группировку, поиск и фильтры в query-параметрах, чтобы вид пересылался ссылкой. Значения по умолчанию в URL не пишутся. |
| `getAssigneeCandidates(...)` | Собирает кандидатов в исполнители из назначенных логинов, списка назначаемых в репозитории и участников доски; склейка без учёта регистра, потому что логины GitHub регистронезависимы. |
| `createLabel(...)` | Заводит метку и вставляет её в список в том же порядке, в каком метки приходят из GitHub. |
| `uploadAsset(...)` | Отправляет картинку `FormData`, чтобы не гонять base64. |
| `save(...)` | Создаёт или обновляет задачу, затем перезагружает доску. |
| `moveTask(...)` | Переносит карточку: правит поле, по которому построены колонки, оптимистично обновляет список и возвращает задачу на место при отказе GitHub. |
| `addColumn(...)` | Создаёт пользовательский статус через `POST /api/board/statuses`. |

## Важные детали

Клиент не знает про [[Архитектура#Служебные лейблы|соглашение о служебных лейблах]]: колонки приходят из `/api/board/statuses`, статус, приоритет и платформы — готовыми полями задачи, а в `labels` остаются только обычные метки. Локально заданы лишь закрытые каталоги приоритетов и платформ — их backend не отдаёт, потому что своих значений в них пользователь не заводит.

Все три режима отображения теперь строятся из одних и тех же колонок `buildColumns`, поэтому переключатель группировки действует в каждом. Разрез по платформам и по исполнителям показывает задачу в каждой её группе, а завершённые во всех разрезах, кроме статуса, выносятся в отдельную колонку — см. [[frontend/Доска#Правила группировки]]. Полоса прогресса подчиняется тому же переключателю. Платформа на карточке и в таблице рисуется контурным чипом, чтобы не путаться с метками GitHub, у которых цвет заливки берётся из самого лейбла.

Кнопка обновления в шапке вызывает тот же `loadBoard`, что и вход: пока запрос идёт, иконка крутится, кнопка заблокирована, а доска сменяется строкой загрузки — отдельного «тихого» обновления нет.

Плюс в колонке открывает обычную модалку создания с заполненным полем этой колонки; заготовку даёт `getColumnDraft`, см. [[frontend/Доска#Правила переноса]]. В колонке «Завершено» плюса нет: новая задача не бывает готовой.

Завершённых задач в репозитории больше сотни, поэтому на доске их колонка показывает три верхние карточки, а остальные прячет за кнопкой «Развернуть». Задачи приходят от GitHub в порядке от новых к старым, отдельной сортировки для этого не нужно. В списке и таблице свёртки нет: там завершённые лежат последней группой и доску вниз не растягивают.

Метка заводится прямо из задачи, для которой понадобилась, и сразу к ней прикрепляется. Формы у чипа нет: поля задачи уже лежат внутри формы модалки, а вложенные формы запрещены — поэтому Enter обрабатывается вручную и не отправляет задачу целиком. Ошибка показывается тут же под чипом: общий баннер ошибки модалка перекрывает.

Кандидаты в исполнители пополняются из `/api/board/assignees`. Контрибьюторы репозитория для этого не годятся — см. [[backend/API]].

Аватар строится из логина ссылкой `https://github.com/<login>.png?size=…`, а не из поля `avatarUrl` задачи: логин есть везде, включая выбор исполнителя и оптимистично перенесённую карточку, а `avatarUrl` — только у уже назначенных. Поэтому поле из API интерфейс не использует. Буква логина на цветном круге осталась под картинкой и видна, пока та грузится или если логина в GitHub нет.

Клиент не выбирает репозиторий и не получает GitHub token: репозиторий и сервисный токен заданы server-side. Development proxy делает браузерный запрос относительным (`/api/...`), поэтому cookie не требует отдельной CORS-настройки Vite-клиента.

Перетаскивание — нативный HTML5 drag & drop, без дополнительной библиотеки. В `dragstart` обязателен `setData`, иначе перетаскивание не стартует в Firefox.

Чего в клиенте пока нет: пагинации, сортировки внутри колонки и переупорядочивания колонок, клавиатурной альтернативы перетаскиванию. Макет рассчитан на ширину от 1100px.
