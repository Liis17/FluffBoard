# Приложение

Parent: [[Index]]

## Назначение

React-клиент FluffBoard показывает защищённую доску задач одной репозитории GitHub. Пользователь входит по локальным учётным данным, затем создаёт, редактирует и переносит задачи; каждая запись сразу отправляется в GitHub. Экран собран по макету редизайна из `docs/handoff_fluffboard_board/`.

## Файлы

- `frontend/src/App.jsx` — состояние экрана, загрузка данных, синхронизация вида с URL и композиция блоков.
- `frontend/src/api.js` — запрос с cookie-сессией и разбор ошибок API.
- `frontend/src/board.js` — чистая логика доски, см. [[frontend/Доска]].
- `frontend/src/index.css` — дизайн-токены как CSS-переменные и базовые стили.
- `frontend/src/App.css` — стили всех блоков экрана.
- `frontend/index.html` — подключение шрифтов Manrope и JetBrains Mono с Google Fonts.
- `frontend/vite.config.js` — React-плагин и proxy `/api` на backend development server.

## Ключевые функции `App.jsx`

| Функция | Описание |
|---|---|
| `readView` / `writeView` | Держат режим, группировку, поиск и фильтры в query-параметрах, чтобы вид пересылался ссылкой. Значения по умолчанию в URL не пишутся. |
| `getAssigneeCandidates(...)` | Собирает кандидатов в исполнители из фактически назначенных логинов и участников доски; склейка без учёта регистра, потому что логины GitHub регистронезависимы. |
| `save(...)` | Создаёт или обновляет задачу, затем перезагружает доску. |
| `moveTask(...)` | Переносит карточку: правит поле, по которому построены колонки, оптимистично обновляет список и возвращает задачу на место при отказе GitHub. |
| `addColumn(...)` | Создаёт пользовательский статус через `POST /api/board/statuses`. |

## Важные детали

Клиент не знает про [[Архитектура#Служебные лейблы|соглашение о служебных лейблах]]: колонки приходят из `/api/board/statuses`, статус, приоритет и платформы — готовыми полями задачи, а в `labels` остаются только обычные метки. Локально заданы лишь закрытые каталоги приоритетов и платформ — их backend не отдаёт, потому что своих значений в них пользователь не заводит.

Все три режима отображения теперь строятся из одних и тех же колонок `buildColumns`, поэтому переключатель группировки действует в каждом. Разрез по платформам и по исполнителям показывает задачу в каждой её группе — см. [[frontend/Доска#Правила группировки]]. Платформа на карточке и в таблице рисуется контурным чипом, чтобы не путаться с метками GitHub, у которых цвет заливки берётся из самого лейбла.

Клиент не выбирает репозиторий и не получает GitHub token: репозиторий и сервисный токен заданы server-side. Development proxy делает браузерный запрос относительным (`/api/...`), поэтому cookie не требует отдельной CORS-настройки Vite-клиента.

Перетаскивание — нативный HTML5 drag & drop, без дополнительной библиотеки. В `dragstart` обязателен `setData`, иначе перетаскивание не стартует в Firefox.

Чего в клиенте пока нет: разметки описания задачи как markdown (в GitHub тело issue — markdown, а поле здесь обычный textarea), пагинации, сортировки внутри колонки и переупорядочивания колонок, клавиатурной альтернативы перетаскиванию. Макет рассчитан на ширину от 1100px.
