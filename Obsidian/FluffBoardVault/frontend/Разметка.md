# Разметка

Parent: [[Index]]

## Назначение

`frontend/src/markdown.js` — чистая логика описания задачи: панель разметки, вставка картинки и рендер markdown. Как и [[frontend/Доска]], функции не знают про React и состояние, поэтому проверяются прогоном в Node. Компонент `MarkdownEditor` остаётся тонким: он владеет только фокусом, выделением и режимом предпросмотра.

## Функции

| Экспорт | Описание |
|---|---|
| `actions` | Каталог кнопок панели: обёртка выделения (`wrap`, либо `before`/`after`) или префикс строк (`prefix`). |
| `applyAction(...)` | Возвращает новое значение поля и выделение, которое нужно восстановить. |
| `insertText(...)` | Вставка на место курсора; выделенный текст заменяется. |
| `imageSnippet(...)` | Разметка загруженной картинки: подписью служит имя файла, как в GitHub. |
| `renderMarkdown(...)` | Markdown → HTML через marked, затем обязательная очистка DOMPurify. |

## Правила разметки

Кнопка либо оборачивает выделение, либо ставит префикс в начало каждой выделенной строки: у списка, чек-листа и цитаты обёртка бессмысленна. Префикс уезжает в начало строки, даже если курсор стоит посреди неё, — иначе список начинался бы с середины текста.

Выделение после вставки восстанавливается по-разному: с выделенным текстом оно остаётся на самом тексте, без выделения курсор встаёт между знаками — можно сразу печатать. После вставки картинки выделения нет, курсор стоит за ссылкой.

Markdown разбирается в режиме GFM с `breaks: true`: тело issue в GitHub устроено так же, там перенос строки значим.

## Очистка HTML

Предпросмотр вставляется как `innerHTML`, поэтому HTML обязательно проходит через DOMPurify. Проверено на `<script>`, атрибуте `onerror`, ссылке `javascript:` и `<iframe>` — всё это вырезается, а ссылки на картинки очистку переживают.

DOMPurify без DOM возвращает строку **как есть**, ничего не вычищая, поэтому в прогоне-проверке браузерное окружение подставляется через jsdom до импорта модуля. В приложении такого случая нет: клиент всегда работает в браузере.

## Вложения

Картинка прикрепляется кнопкой панели или вставкой из буфера — браузер отдаёт её файлом в `clipboardData.files`. Файл уходит на `POST /api/board/assets` через `FormData`, а ссылка на него подставляется в разметку. Позиция курсора запоминается до запроса: пока идёт загрузка, поле можно расфокусировать. Где хранятся сами файлы — см. [[backend/API]].
