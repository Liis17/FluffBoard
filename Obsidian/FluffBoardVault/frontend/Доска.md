# Доска

Parent: [[Index]]

## Назначение

`frontend/src/board.js` — чистая логика доски: фильтрация, группировка, метрики и вывод цветов. Функции не знают про React и состояние, поэтому проверяются прогоном в Node без браузера. Соответствуют `docs/handoff_fluffboard_board/03-state-and-data.md`.

## Каталоги

| Экспорт | Содержимое |
|---|---|
| `priorities` | Пять уровней в порядке `urgent → high → medium → low → none`: подпись, глиф и цвета из макета. |
| `platforms` | Шесть платформ в порядке от сервера к клиентам: подпись и цвет. Дублирует `PlatformCatalog` из [[backend/GitHubClient]] — там каталог нужен для валидации и цвета label, здесь для отображения. Так же устроен `priorities`. |
| `groupings` | Статус, платформа, исполнитель, лейбл. |
| `views` | Доска, список, таблица. |
| `unassignedKey` / `unlabelledKey` / `noPlatformKey` | Ключи служебных колонок «Не назначен», «Без лейбла» и «Без платформы». |

## Функции

| Функция | Описание |
|---|---|
| `visibleTasks(...)` | Фильтр по строке поиска (заголовок **или** номер задачи) и по лейблам с логикой AND. |
| `buildColumns(...)` | Строит колонки по выбранной группировке. |
| `getMoveOverrides(...)` | Что меняется при переносе карточки; `null`, если менять нечего. |
| `toPayload(...)` | Полное тело запроса: `PUT` заменяет задачу целиком, поэтому передаются все поля. |
| `applyOverrides(...)` | Оптимистичная копия задачи в форме, которую ждёт интерфейс. |
| `getMetrics(...)` | Пять плиток. Считаются по всем задачам, а не по отфильтрованным. |
| `getProgress(...)` | Процент готового и доли сегментов полосы. |
| `getLabelColors(...)` | Из одного hex GitHub выводит пару фон/текст. |
| `getAvatarColor(...)` | Детерминированный цвет аватара из логина. |
| `getPlatform(...)` | Запись каталога по ключу. В отличие от `getPriority` не имеет fallback: неизвестные ключи отбрасывает уже backend. |

## Правила группировки

- **Статус** — колонка на каждый элемент `/api/board/statuses`, совпадение по `issue.status`.
- **Платформа** — колонка на каждый элемент каталога плюс «Без платформы». Порядок фиксирован каталогом, а не данными, поэтому пустые платформы всё равно занимают своё место в доске (в списке и таблице пустые группы скрываются).
- **Исполнитель** — колонка на каждого кандидата плюс «Не назначен».
- **Лейбл** — колонка на каждую метку плюс «Без лейбла». В макете последней нет, но на реальных данных задачи без меток есть, и терять их нельзя.

**Многозначные разрезы.** Платформа и исполнитель — многозначные: задача попадает в каждую свою колонку, поэтому сумма карточек больше числа задач. Это не дубликаты, а один и тот же issue, показанный в нескольких разрезах, — правка в любом из них правит одну задачу.

## Правила переноса

Перетаскивание правит именно то поле, по которому построены колонки:

| Группировка | Что меняется |
|---|---|
| статус | `status` = ключ колонки |
| платформа | платформа **добавляется** к имеющимся; повторное добавление игнорируется |
| исполнитель | `assignees` перезаписывается одним логином, либо очищается для «Не назначен» |
| лейбл | лейбл **добавляется** к имеющимся, а не заменяет их; повторное добавление игнорируется |

Платформа добавляется, а не заменяет: задачи, честно относящиеся сразу к нескольким платформам, — норма, и перенос не должен это стирать. Исполнитель ведёт себя иначе, потому что перенос в чужую колонку читается как передача задачи.

Колонки «Без лейбла» и «Без платформы» не принимают сброс: это означало бы снять все лейблы или все платформы разом, чего никто не ожидает. Такие колонки помечены `droppable: false` и не подсвечиваются при переносе. «Не назначен» сброс принимает — снять единственного исполнителя это осмысленное действие.

## Цвета лейблов

У лейбла в GitHub только один hex, а чипу нужны фон и текст. `getLabelColors` подмешивает цвет к белому на 18% для фона и затемняет тот же цвет до контраста не ниже 4.5:1 для текста — требование `04-integration.md`. Проверено на всех метках репозитория, включая почти белый `bots` и яркий `MVP`.
