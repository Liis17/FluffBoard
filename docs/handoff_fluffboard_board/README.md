# Handoff: Fluffboard — доска задач (GitHub Issues)

## Что это

Редизайн экрана «Доска задач» для Fluffboard — веб-клиента, который читает и пишет
задачи как GitHub Issues. Макет заменяет текущий тёмный экран (см.
`reference/original-board-dark.png`) на светлый, плотный, «linear-подобный» интерфейс
с тремя режимами отображения, группировкой, фильтрами и полным CRUD задач.

## Про файлы в этом бандле

Файлы в `mock/` — **дизайн-референс, сделанный на HTML**. Это прототип, показывающий
задуманный вид и поведение, а НЕ продакшн-код для копирования.

Задача принимающего агента/разработчика: **воспроизвести этот макет в существующем
окружении реального проекта** (React / Vue / Svelte / что там есть) его же паттернами,
роутингом, стейт-менеджером и библиотеками. Разметка макета написана в собственном
шаблонном формате (`.dc.html`, теги `<sc-for>`, `<sc-if>`, `{{ }}`) — переносить
её дословно не нужно и нельзя; переносятся **токены, размеры, состояния и логика**,
которые задокументированы в этих `.md`.

Как открыть прототип: `mock/Fluffboard.dc.html` открывается прямо в браузере
(рядом должен лежать `mock/support.js`). Всё интерактивно, данные — моковые, в памяти.

## Точность (fidelity)

**High-fidelity.** Цвета, типографика, отступы, радиусы, тени и состояния — финальные,
их надо повторять точно (значения в `01-tokens.md`). Исключение — если в проекте уже
есть своя дизайн-система: тогда сначала маппим токены макета на существующие переменные
проекта, а не плодим новые.

## Экраны и режимы

Один экран, три режима отображения (переключатель в тулбаре, состояние `view`):

1. **Доска** (`board`, по умолчанию) — горизонтальные колонки, drag & drop карточек.
2. **Список** (`list`) — сгруппированные плотные строки.
3. **Таблица** (`table`) — плоская сетка 6 колонок, без группировки.

Плюс два модальных окна: «Новая задача» и «Просмотр/редактирование задачи».

Подробная анатомия каждого блока — `02-components.md`.
Состояние, данные, поведение — `03-state-and-data.md`.
Порядок внедрения и маппинг на GitHub API — `04-integration.md`.

## Ключевые продуктовые решения макета

- **Приоритет — первичный сигнал.** Цветная левая кромка карточки (3px) + пилюля с
  иконкой. Пять уровней: Срочно / Высокий / Средний / Низкий / Без.
- **Группировка отвязана от статуса.** Колонки строятся из `groupBy`:
  статус | исполнитель | лейбл. Drag & drop меняет именно то поле, по которому
  сгруппировано (перетащил в колонку исполнителя — сменился assignee).
- **Прогресс-полоса** — сегментированная по статусам, не один общий бар.
- **Плитки-метрики** сверху (5 шт.) считаются из данных, не хардкод.
- **Модалки по центру**, скролл внутри, футер sticky.
- Тексты интерфейса — по-русски, стиль короткий, без восклицаний (см. точные строки
  в `02-components.md`).

## Ассеты

- `reference/original-board-dark.png` — скриншот текущего (старого) экрана, для
  сравнения «до/после». В макете не используется.
- Иконок-файлов нет: единственная svg-иконка (лупа поиска) нарисована инлайном,
  приоритеты и внешняя ссылка — текстовые глифы (`🔥 ↑ = ↓ · ↗`, `×`).
  В реальном проекте заменить на его иконочный набор, кегль/цвет сохранить.
- Шрифты: Manrope (400/500/600/700/800) и JetBrains Mono (500/600) с Google Fonts.
