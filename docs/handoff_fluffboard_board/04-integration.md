# 04 — Как внедрять

## Порядок работ

1. **Токены.** Перенести палитру, типографику, радиусы и тени из `01-tokens.md` в
   тему проекта (CSS-переменные / tailwind theme / styled theme). Если своя дизайн-система
   уже есть — сначала маппинг на её токены, новые значения добавлять только при отсутствии
   аналога. Подключить Manrope + JetBrains Mono (или ближайшие уже используемые шрифты,
   сохранив веса и кегли).
2. **Атомы.** `PriorityPill`, `LabelChip`, `Avatar` / `AvatarStack`, `Chip` (переключатель),
   `Pill` (выбор статуса/приоритета), `Tabs`, `SearchInput`, `StatTile`.
3. **Молекулы.** `TaskCard`, `ColumnHeader`, `ListRow`, `TableRow`, `ProgressBar`.
4. **Экран.** Шапка → метрики → тулбар → фильтры → прогресс → `BoardView` / `ListView` /
   `TableView`. Логика фильтрации и группировки — чистые функции над массивом задач
   (`visibleTasks`, `buildColumns` из `03-state-and-data.md`), покрыть юнит-тестами.
5. **Модалки.** `NewTaskModal`, `TaskModal` — одна общая форма полей (статус, приоритет,
   лейблы, исполнители), разные футеры и заголовки.
6. **Drag & drop.** В макете — нативный HTML5 DnD. В проекте лучше взять то, что уже
   используется (dnd-kit / pragmatic-drag-and-drop); поведение и подсветку сохранить.
7. **Данные.** Заменить сид на реальный источник, добавить состояния загрузки/ошибок
   и оптимистичные апдейты.

## Маппинг на GitHub Issues

| Поле макета | GitHub |
|---|---|
| `num` | `issue.number` |
| `title` | `issue.title` |
| `desc` | `issue.body` (markdown; в макете plain textarea — при рендере описания нужен markdown) |
| `people` | `issue.assignees[].login` |
| `labels` | `issue.labels[].name` (+ `.color` — см. ниже) |
| `status` | **нет прямого аналога.** Варианты: (а) Projects v2 single-select поле Status; (б) служебные лейблы `status:todo` / `status:in-progress` + `state=closed` для «Готово». Выбрать до начала работ — от этого зависит и drag & drop, и «+ Колонка» |
| `prio` | тоже нет: лейблы `priority:urgent…` или поле в Projects v2. Маппинг ключей 1:1 с таблицей приоритетов |
| «Удалить» | у issue нет удаления через обычный API → закрывать issue (`state: closed`) и переименовать кнопку, либо оставить удаление только для Projects-элемента |
| «GitHub ↗» | `issue.html_url`, открывать в новой вкладке (`target="_blank" rel="noopener"`) |

**Цвета лейблов.** В макете 8 лейблов с ручной парой фон/текст. У GitHub есть только один
hex на лейбл. Правильный перенос: фон = `#RRGGBB` лейбла с прозрачностью ~18–20%
(или подмешать к белому), текст = тот же hex, затемнённый до контраста ≥4.5:1
(например, через oklch: сохранить hue, снизить lightness). Ручную таблицу из
`01-tokens.md` использовать как ожидаемый эталон — сгенерированные цвета должны
выглядеть так же по насыщенности.

**Смена статуса при drop** — один мутирующий запрос; UI обновлять оптимистично и
откатывать при ошибке (карточка возвращается в исходную колонку + тост).

## Чек-лист приёмки

- [ ] Все три режима переключаются, состояние вида живёт в URL.
- [ ] Группировка по статусу / исполнителю / лейблу даёт корректные колонки и счётчики.
- [ ] Поиск ищет и по тексту, и по номеру (`318` находит #318).
- [ ] Фильтр по лейблам работает как AND, «сбросить» появляется только при активном фильтре.
- [ ] Левая кромка карточки, пилюля приоритета и легенда прогресса используют точные hex из `01-tokens.md`.
- [ ] Метрики и прогресс считаются по всем задачам, а не по отфильтрованным.
- [ ] Drag & drop: подсветка колонки-цели, `opacity:.4` у источника, корректное поле меняется по `groupBy`, изменение доходит до GitHub.
- [ ] Создание: пустое название не создаёт задачу; новая задача появляется сверху.
- [ ] Редактирование: правки применяются только по «Сохранить», по «Закрыть» — теряются.
- [ ] Модалки: закрытие по скриму, ×, `Esc`; фокус заперт внутри; sticky-футер при длинном содержимом.
- [ ] «Ссылка GitHub» в карточке не открывает модалку.
- [ ] «+ Колонка» показывается только при группировке по статусу и не использует `window.prompt`.
- [ ] Есть загрузка, пустое состояние и обработка ошибок (в макете их нет — дизайнить по своей системе).
- [ ] Кегль текста нигде не ниже 10px; контраст текста на цветных чипах ≥4.5:1.
