# 03 — Данные, состояние, поведение

## Модель задачи

```ts
type Priority = 'urgent' | 'high' | 'medium' | 'low' | 'none';

type Task = {
  id: number;            // внутренний id (в реале — id issue)
  num: number;           // номер issue, показывается как #318
  title: string;
  desc: string;          // markdown-тело issue
  status: string;        // ключ колонки: 'todo' | 'progress' | 'done' | пользовательская
  prio: Priority;
  labels: { name: string }[];
  people: string[];      // логины исполнителей
};

type Status = { key: string; name: string; dot: string };  // dot — hex цвета
```

## Состояние экрана

| Ключ | Тип | Дефолт | Смысл |
|---|---|---|---|
| `view` | `'board'｜'list'｜'table'` | `'board'` | режим отображения |
| `groupBy` | `'status'｜'assignee'｜'label'` | `'status'` | по какому полю строятся колонки/группы |
| `query` | string | `''` | строка поиска |
| `filters` | string[] | `[]` | выбранные лейблы (AND) |
| `statuses` | Status[] | 3 статуса | колонки при группировке по статусу |
| `tasks` | Task[] | сид из 12 задач | данные |
| `showNew` | boolean | false | открыта модалка создания |
| `draft` | черновик | `{title:'',desc:'',status:'todo',prio:'medium',labels:[],people:[]}` | форма создания |
| `edit` | копия задачи `｜null` | null | форма редактирования; `labels` здесь **массив строк**, не объектов |
| `openId` | number `｜null` | null | id открытой задачи |
| `overCol` | string `｜null` | null | колонка под курсором при drag |

Стейт локальный, экранного уровня. В реальном проекте: `tasks`/`statuses` — серверные
данные (react-query / стор), остальное — UI-стейт. `view`, `groupBy`, `query`, `filters`
стоит держать в URL-параметрах, чтобы вид шарился ссылкой (в макете этого нет).

## Пайплайн отображения

1. **Фильтрация** `visibleTasks()`: по `query` — `title.toLowerCase().includes(q)` ИЛИ
   `String(num).includes(q)`; по `filters` — задача проходит, только если содержит **все**
   выбранные лейблы.
2. **Группировка** `buildColumns()` по `groupBy`:
   - `status` — колонка на каждый элемент `statuses`, совпадение `task.status === key`;
   - `assignee` — колонка на каждого известного участника + служебная **«Не назначен»**
     (ключ `__none`, точка `#94a3b8`) для задач с пустым `people`. Задача с несколькими
     исполнителями попадает в несколько колонок — это осознанно;
   - `label` — колонка на каждый известный лейбл. Задачи без лейблов не показываются —
     при переносе на реальные данные добавить колонку «Без лейбла».
3. **Декорирование** `decorate()`: к задаче добавляются готовые стили/подписи (цвет кромки,
   пилюли, чипы лейблов, аватары, строка исполнителей, название и цвет статуса).
   В React это должно быть не «стили в данных», а обычные компоненты `TaskCard`,
   `LabelChip`, `PriorityPill`, `AvatarStack`.

Важно: метрики и прогресс считаются по **всем** задачам (`tasks`), а не по отфильтрованным.
Таблица показывает отфильтрованные задачи без группировки.

## Действия

| Действие | Триггер | Что происходит |
|---|---|---|
| Поиск | ввод в поле | `query` = значение, пересчёт колонок на каждый ввод (debounce при серверном поиске) |
| Смена режима | таб | `view` |
| Смена группировки | `<select>` | `groupBy`, сброс `overCol` |
| Фильтр по лейблу | клик по чипу | добавить/убрать лейбл в `filters` |
| Сбросить фильтры | «сбросить» | `filters = []` |
| Открыть задачу | клик по карточке/строке | `openId` + `edit` = копия задачи (`labels` → массив имён) |
| Ссылка GitHub | клик | `preventDefault` + `stopPropagation`, карточка не открывается. В реале — ссылка на issue в новой вкладке |
| Drag start | начало перетаскивания | запомнить id, `effectAllowed='move'`, `opacity:.4` |
| Drag over колонки | — | `preventDefault`, `overCol` = ключ колонки (подсветка границы) |
| Drop | отпустить над колонкой | `moveTask(id, key)`, `overCol=null` |
| Добавить колонку | «+ Колонка» | `window.prompt` с дефолтом «На проверке» → новый статус с цветом из палитры. **В реальном проекте prompt заменить на модалку/поповер с полем и выбором цвета.** |
| Создать задачу | «Создать задачу» | если название непустое: `num = max(num, 300) + 1`, задача добавляется в **начало** списка, модалка закрывается, черновик сбрасывается |
| Сохранить задачу | «Сохранить» | если название непустое: применить title/desc/status/prio/labels/people, закрыть модалку |
| Удалить задачу | «Удалить» | удалить из `tasks`, закрыть модалку. **В реале нужны подтверждение и, для GitHub, закрытие issue вместо удаления** |
| Закрыть модалку | ×, «Отмена», «Закрыть», клик по скриму | сброс `showNew` / `edit`+`openId` |

### `moveTask(id, key)` — зависит от группировки

- `groupBy === 'status'` → `status = key`;
- `groupBy === 'assignee'` → `people = key === '__none' ? [] : [key]` (перезаписывает всех исполнителей);
- `groupBy === 'label'` → лейбл `key` **добавляется** (не заменяет остальные), повторное добавление игнорируется.

## Чего в макете нет и что надо добавить в реальном проекте

- загрузка/скелетоны, пустое состояние всей доски, ошибки и ретраи;
- оптимистичные апдейты + откат при неудачном запросе к GitHub;
- пагинация/бесконечная прокрутка (в реальном проекте счётчики вида «60 / 123» —
  см. `reference/original-board-dark.png`, задач много);
- права доступа (кто может двигать и удалять);
- адаптив: макет рассчитан на ширину ≥1100px. Ниже — колонки уходят в горизонтальный
  скролл (это уже так), тулбар переносится, таблицу на мобильном заменить режимом «Список»;
- доступность: фокус-ловушка и `Esc` в модалках, `aria-label` на иконочных кнопках,
  клавиатурная альтернатива drag & drop (меню «Переместить в…»), `role`/`aria-selected`
  на табах;
- сортировка внутри колонки (в макете — порядок массива) и сохранение порядка.
